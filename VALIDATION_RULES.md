# Validation Rules - System Management

## Database Analysis Summary

From Phase 2 database discovery:

### Systems Table
- **Primary Key**: `asset_uid` (UUID)
- **No other unique constraints** - manufacturer+model can have duplicates (query #10 returned no results)
- **All fields nullable except**: `asset_uid`, `manual`
- **Field population rates** (out of 142 total systems):
  - 100% populated: system_norm, subsystem_norm, manufacturer_norm, model_norm, canonical_model_id (142/142)
  - 92% populated: description (130/142)
  - 52% populated: spec_keywords (74/142)
  - 42% populated: oem_page (59/142)
  - 25% populated: manual_url (35/142)

### Instances Table
- **Primary Key**: `instance_uid` (UUID)
- **Foreign Key**: `asset_uid` → `systems.asset_uid`
- **All fields nullable except**: `instance_uid`, `asset_uid`
- **Relationship**: One system can have multiple instances (1 to many)
- **Most common instance counts**: 10, 8, 7, 7, 6, 3, 3, 3, 3, 3

### Instances Archived Table
- **Status**: Does not exist - needs to be created
- **SQL**: See create-instances-archived.sql

## Validation Rules for Phase 3

### Systems - CREATE (New System)

#### Required Fields
1. **manufacturer_norm** - MUST be non-empty string
2. **model_norm** - MUST be non-empty string
3. **system_norm** - MUST be non-empty string
4. **subsystem_norm** - MUST be non-empty string
5. **canonical_model_id** - MUST be non-empty string

#### Optional Fields (can be null/empty)
- description
- manual_url (if provided, must be valid URL)
- oem_page (if provided, must be valid URL)
- spec_keywords
- synonyms_fts
- synonyms_human
- spec_keywords_jsonb (if provided, must be valid JSON)
- synonyms_jsonb (if provided, must be valid JSON)

#### Auto-Generated Fields
- **asset_uid**: Generate new UUID v4 on server
- **manual**: Default to false
- **search**: Auto-generated by database trigger (tsvector)

#### Business Rules
1. No uniqueness constraint on manufacturer+model - duplicates ARE allowed
2. All text fields should be trimmed
3. Empty strings should be converted to NULL for optional fields
4. URLs must start with http:// or https://
5. JSON fields must parse successfully if not empty

### Systems - UPDATE (Edit Existing)

#### Immutable Fields (cannot be changed)
- **asset_uid** - Primary key, never changes

#### Updateable Fields
- All other fields can be updated following the same validation as CREATE

#### Business Rules
1. Must provide valid asset_uid that exists
2. Cannot change asset_uid
3. Follow same validation as CREATE for all other fields

### Instances - CREATE

#### Required Fields
1. **asset_uid** - MUST exist in systems table

#### Optional Fields
- serial_number
- location
- instance_index (auto-increment within asset_uid if not provided)

#### Auto-Generated Fields
- **instance_uid**: Generate new UUID v4 on server
- Other normalized fields (system_norm, manufacturer_norm, etc.) copied from parent system

#### Business Rules
1. If instance_index not provided, auto-assign as MAX(instance_index) + 1 for that asset_uid
2. serial_number and location can both be null
3. Foreign key constraint ensures asset_uid exists

### Instances - UPDATE

#### Immutable Fields
- **instance_uid** - Primary key
- **asset_uid** - Foreign key, cannot change parent system

#### Updateable Fields
- serial_number
- location
- instance_index

### Instances - DELETE (Archive)

#### Process
1. Copy full instance record to instances_archived table
2. Set archived_at to NOW()
3. Set archived_by (from user context if available)
4. Store original_data as JSONB (complete instance record)
5. DELETE from instances table

#### Business Rules
1. NEVER hard delete without archiving first
2. Cascade behavior: If system deleted, archive all instances first
3. archived_by should be set to system identifier if user context unavailable

## Frontend Validation (Phase 4)

### Red X Indicators Should Show For:
1. Empty required fields (manufacturer_norm, model_norm, system_norm, subsystem_norm, canonical_model_id)
2. Invalid URL format (manual_url, oem_page)
3. Invalid JSON format (spec_keywords_jsonb, synonyms_jsonb)
4. Asset UID not found (on edit mode)

### Error Messages
- "This field is required"
- "Invalid URL format"
- "Invalid JSON format"
- "System not found"
- "Failed to save: [detailed error from backend]"

## Backend Response Format

### Success Response
```json
{
  "success": true,
  "data": {
    "asset_uid": "uuid-here",
    "message": "System created successfully"
  },
  "requestId": "request-uuid"
}
```

### Validation Error Response
```json
{
  "success": false,
  "error": "Validation failed",
  "validationErrors": {
    "manufacturer_norm": "This field is required",
    "manual_url": "Invalid URL format"
  },
  "requestId": "request-uuid"
}
```

### System Error Response
```json
{
  "success": false,
  "error": "Database error: [specific error]",
  "requestId": "request-uuid"
}
```
