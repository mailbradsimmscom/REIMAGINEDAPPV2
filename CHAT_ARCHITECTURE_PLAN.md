# Bulletproof Chat Architecture Plan

## Critical Requirements

### ID Generation
- **Frontend creates ALL IDs** - No negotiation, no exceptions
- Thread ID: Generated by frontend JavaScript on new chat (UUID.v4())
- Session ID: Generated by frontend JavaScript on new chat (UUID.v4())
- Message sequence: Frontend tracks sequential numbering (1,2,3,4...)

### Message Persistence
- **Every message saved BEFORE anything else happens**
- Synchronous saves with explicit confirmation
- No background promises that can fail silently
- User message saved FIRST, then Python call, then assistant response saved

### Sequential Numbering
- Messages numbered 1,2,3,4... within each thread
- No gaps, no confusion, strict sequential order
- Database enforces sequence integrity
- Message pairs: (1,2), (3,4), (5,6) for summary generation

### Context Management
- System info from equipment mentioned in thread
- Progressive summaries with decay weights
- Decreasing importance function for older summaries
- Complete context passed to Python as structured input

### Error Recovery
- If Python fails, chat history remains intact
- Every save operation verified with success/failure handling
- Rollback user message if Python call fails
- Clear error messages to user about system state

### Thread State
- Node.js owns ALL conversation state
- Python is stateless - receives context, returns response only
- Thread management in Node.js database tables
- No state synchronization between services

## Current System Failure Points

1. **Multiple services creating IDs** = Guaranteed conflicts
2. **Background promises for saving** = Messages lost silently
3. **No sequential numbering** = Can't build proper summaries
4. **No verification of saves** = Don't know what's actually stored
5. **Python generating IDs** = Sync issues with Node.js database
6. **ensureSessionAndThread complexity** = Creating wrong IDs

## Implementation Plan

### Phase 1: Clean Architecture Reset
```
REMOVE:
- Python UUID generation (main.py lines 738-739)
- ensureSessionAndThread complexity (chat-proxy.service.js)
- Background Promise.all saves (chat-proxy.service.js lines 278-295)
- Equipment inference complexity
```

### Phase 2: Frontend ID Management
```
IMPLEMENT IN app.js:
- generateThreadId() using crypto.randomUUID()
- generateSessionId() using crypto.randomUUID()
- Track messageSequenceNumber starting at 1
- Send threadId, sessionId, sequenceNumber on every request
```

### Phase 3: Synchronous Message Flow
```
NEW FLOW:
1. User types message
2. Frontend: Save user message to DB (await confirmation)
3. Frontend: Call Python with context (only if save succeeded)
4. Frontend: Save assistant response to DB (await confirmation)
5. Frontend: Update UI (only if both saves succeeded)
6. Background: Generate thread name after first exchange
```

### Phase 4: Context Assembly
```
NODE.JS RESPONSIBILITIES:
- Retrieve system context from equipment mentioned in thread
- Build progressive summaries: pairs (1,2), (3,4), (5,6)
- Apply decay weights: recent=1.0, last_2=0.8, last_5=0.5, older=0.2
- Pass structured context to Python
- Python returns response only, no state management
```

### Phase 5: Database Schema
```
REQUIRED CHANGES:
- chat_messages.sequence_number (INTEGER, NOT NULL)
- chat_threads.message_count (INTEGER, DEFAULT 0)
- Index on (thread_id, sequence_number)
- Foreign key constraints for referential integrity
```

## Non-Negotiables

1. **Frontend generates thread_id** - Period
2. **Every message saved synchronously** - With confirmation
3. **Sequential numbering enforced** - 1,2,3,4... no gaps
4. **Node.js owns conversation state** - Single source of truth
5. **Python is stateless** - Receives context, returns response
6. **No message proceeds without DB confirmation** - Zero data loss

## Why This Matters

Without reliable chat history → Can't build summaries
Without summaries → Context gets lost
Without context → DIP system can't provide accurate equipment-specific answers
**The entire value proposition collapses**

The chat interface isn't a feature - **it's THE critical path**.

## Success Metrics

- **100% message persistence** - No lost messages ever
- **Sequential integrity** - No gaps in numbering
- **Context accuracy** - System info + summaries always current
- **Error transparency** - User always knows system state
- **Zero ID conflicts** - Frontend is single source of truth

## Implementation Order

1. **Stop Python ID generation** - Immediate
2. **Implement frontend ID management** - Before any other changes
3. **Replace ensureSessionAndThread** - With simple CREATE operations
4. **Make saves synchronous** - Block until confirmed
5. **Add sequence numbering** - Database schema + logic
6. **Build context assembly** - Progressive summaries with decay
7. **Add error recovery** - Rollback on failures

**This requires a complete rewrite of the chat flow, but it's the only way to ensure reliability.**

```javascript
export async function getMessagesByThreadWithSequence(threadId, options = {}) {
  try {
    const supabase = await checkSupabaseAvailability();
    const { limit = 50, startSequence, endSequence } = options;

    let query = supabase
      .from(MESSAGES_TABLE)
      .select('*')
      .eq('thread_id', threadId)
      .order('sequence_number', { ascending: true });

    if (startSequence) {
      query = query.gte('sequence_number', startSequence);
    }

    if (endSequence) {
      query = query.lte('sequence_number', endSequence);
    }

    query = query.limit(limit);

    const { data, error } = await query;

    if (error) throw new Error(`Failed to get messages: ${error.message}`);
    return data ?? [];
  } catch (error) {
    throw error;
  }
}
```

## 7. Context Assembly Service (NEW FILE)

### File: `src/services/context-assembly.service.js`
**Purpose:** Build progressive summaries with decay weights

```javascript
import { getMessagesByThreadWithSequence } from '../repositories/chat.repository.js';
import { oaiText } from '../clients/openai.client.js';
import { logger } from '../utils/logger.js';

const DECAY_WEIGHTS = {
  current: 1.0,
  last_2_exchanges: 0.8,
  last_5_exchanges: 0.5,
  older_exchanges: 0.2
};

export async function buildContextWithProgressiveSummaries(threadId, currentSequence) {
  try {
    // Get all messages for the thread
    const messages = await getMessagesByThreadWithSequence(threadId);

    if (messages.length === 0) {
      return {
        summaries: [],
        total_exchanges: 0,
        equipment_context: []
      };
    }

    // Group messages into exchanges (pairs: user + assistant)
    const exchanges = [];
    for (let i = 0; i < messages.length; i += 2) {
      if (i + 1 < messages.length) {
        exchanges.push({
          user: messages[i],
          assistant: messages[i + 1],
          sequence_start: messages[i].sequence_number,
          sequence_end: messages[i + 1].sequence_number
        });
      }
    }

    // Build summaries with decay weights
    const summaries = [];
    const totalExchanges = exchanges.length;

    for (let i = 0; i < exchanges.length; i++) {
      const exchange = exchanges[i];
      const exchangesFromEnd = totalExchanges - i - 1;

      // Determine weight based on recency
      let weight;
      if (exchangesFromEnd === 0) {
        weight = DECAY_WEIGHTS.current;
      } else if (exchangesFromEnd <= 2) {
        weight = DECAY_WEIGHTS.last_2_exchanges;
      } else if (exchangesFromEnd <= 5) {
        weight = DECAY_WEIGHTS.last_5_exchanges;
      } else {
        weight = DECAY_WEIGHTS.older_exchanges;
      }

      // Generate summary for this exchange
      const summary = await summarizeExchange(
        exchange.user.content,
        exchange.assistant.content,
        exchange.assistant.metadata
      );

      summaries.push({
        exchange_number: i + 1,
        sequence_range: [exchange.sequence_start, exchange.sequence_end],
        summary,
        weight,
        equipment_mentioned: extractEquipmentFromMetadata(exchange.assistant.metadata)
      });
    }

    // Extract all equipment mentioned across conversation
    const allEquipment = summaries.flatMap(s => s.equipment_mentioned);
    const uniqueEquipment = deduplicateEquipment(allEquipment);

    return {
      summaries,
      total_exchanges: totalExchanges,
      equipment_context: uniqueEquipment
    };

  } catch (error) {
    logger.error('Failed to build context with progressive summaries', {
      threadId,
      error: error.message
    });
    throw error;
  }
}

async function summarizeExchange(userQuery, assistantResponse, metadata) {
  try {
    const prompt = `Summarize this Q&A exchange in 1-2 sentences focusing on equipment and topic:

User: ${userQuery}
Assistant: ${assistantResponse.substring(0, 500)}

Summary:`;

    const summary = await oaiText({
      system: 'You summarize technical Q&A exchanges concisely.',
      user: prompt,
      model: 'gpt-4o-mini',
      maxOutputTokens: 100
    });

    return summary.trim();
  } catch (error) {
    logger.warn('Failed to generate exchange summary', { error: error.message });
    return `User asked about: ${userQuery.substring(0, 100)}`;
  }
}

function extractEquipmentFromMetadata(metadata) {
  if (!metadata || !metadata.systems_context) return [];

  return metadata.systems_context.map(eq => ({
    asset_uid: eq.asset_uid,
    manufacturer: eq.manufacturer,
    model: eq.model,
    rank: eq.rank || 1.0
  }));
}

function deduplicateEquipment(equipment) {
  const seen = new Set();
  const unique = [];

  for (const eq of equipment) {
    if (!seen.has(eq.asset_uid)) {
      seen.add(eq.asset_uid);
      unique.push(eq);
    }
  }

  return unique;
}
```

## 9. Database Functions (Supabase SQL)

### Function: `increment_thread_message_count`
```sql
CREATE OR REPLACE FUNCTION increment_thread_message_count(thread_id_param UUID)
RETURNS VOID AS $$
BEGIN
  UPDATE chat_threads
  SET message_count = message_count + 1,
      updated_at = NOW()
  WHERE id = thread_id_param;
END;
$$ LANGUAGE plpgsql;
```

### Function: `decrement_thread_message_count`
```sql
CREATE OR REPLACE FUNCTION decrement_thread_message_count(thread_id_param UUID)
RETURNS VOID AS $$
BEGIN
  UPDATE chat_threads
  SET message_count = GREATEST(message_count - 1, 0),
      updated_at = NOW()
  WHERE id = thread_id_param;
END;
$$ LANGUAGE plpgsql;
```
